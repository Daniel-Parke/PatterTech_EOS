# Reference: what a compromised build system can reach

Level 3 detail behind binding requirement B4. Every other control in
this pack assumes the build is honest. Provenance generated by a
compromised build is accurate provenance about a compromised build, and
it will verify. So this is the one place where the control is
configuration rather than cryptography, and it is also the cheapest
work in the pack.

## The reach, written down

Start by listing what the build can touch, because the answer is
usually larger than anyone assumed:

- **Every secret configured on the repository.** The platform's own
  guidance states that anyone with write access can read all of them.
  Scoping a secret to an environment helps; assuming a secret is
  private because it is not printed does not.
- **The publishing credential and the signing identity.** If these are
  reachable from any job, they are reachable from the compromised one.
- **The registries the build can push to**, which includes every
  package, image and artefact destination the token is scoped for.
- **The deployment targets**, if the same platform deploys.
- **The source repository itself**, where the token has write scope,
  which means the compromise can persist by editing the workflow.
- **The cache.** A poisoned build cache outlives the run that poisoned
  it and is restored into later builds, including ones on other
  branches.
- **The runner's disk and memory**, indefinitely, on a self-hosted
  runner. The platform states plainly that self-hosted runners offer no
  isolation guarantee and can be persistently compromised.

## The routes in

- **A third-party build step referenced by a mutable tag.** The step's
  owner, or anyone who compromises them, changes what that tag points
  at. Only a full commit digest is immutable.
- **Untrusted text from a pull request reaching a shell.** Title, branch
  name, body, author name. The platform's guidance is to route it
  through an intermediate variable or a dedicated step rather than
  interpolating it into a command.
- **A workflow trigger that runs a fork's code with the base
  repository's secrets.** This is the classic one and it is a trigger
  choice, not an accident.
- **A dependency that runs code at install time.** Several ecosystems
  execute scripts during installation, so the build is compromised
  before it builds anything.
- **A compromised maintainer account upstream.** Nothing in this file
  prevents it; the cooldown in GD-SUPPLY-003 is what buys time against
  it.

## Containment worth having

Ordered by ratio of benefit to effort, best first:

1. **The default token starts read-only**, widened per job. One line.
2. **Publishing and signing live in a job that nothing untrusted can
   reach**, and preferably in a separate workflow triggered by a tag,
   not by a pull request.
3. **Third-party steps pinned to commit digests**, updated by a bot.
4. **No self-hosted runner serves a public repository.** The platform
   says this outright.
5. **Untrusted input never interpolated into a shell.**
6. **Build and publish separated**, so the job that compiles is not the
   job that holds the credential. The artefact digest is what crosses
   between them.
7. **Read the repository before depending on it** (EV-0069). Who can
   publish, whether releases are automated, whether the project is
   alive. A project's description of its own practices is not evidence
   about its practices.

## The failure this prevents

A compromised build that can sign is the single failure that defeats
every other control in this pack at once, because the artefact will
carry valid provenance from the real workflow and a valid signature
from the real identity, and every consumer check will pass. There is no
downstream verification that catches it. That is why B4 is binding and
why the reach above is worth writing out for a specific venture rather
than reading in the abstract.

## The one signal that survives it

If the compromise changes how a release is published, a consumer
watching the publishing path can see it: publisher, repository,
workflow, whether provenance appeared or disappeared. The measurement
behind this pack found that comparing consecutive releases on those
attributes surfaced a usable number of cases worth reviewing. Its
authors also state where it is blind, and the blindness is exactly this
case: a compromise that reuses the same publishing path leaves nothing
to compare. So it is a prompt to look, not a control, and it is in the
pack's defaults rather than its binding set for that reason.
