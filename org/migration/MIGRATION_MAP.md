# MIGRATION_MAP

What happened to every part of EOS v1 under ADR-0002. This is the
reference the per-venture migration playbook cites, and the answer to
"where did that rule go" for anyone who learned the system in July.

Five fates are used, and a retired concept always names where its
load-bearing rule now lives. Nothing was dropped silently.

- **survive**: the same thing, still binding.
- **change**: the same job, a new mechanism.
- **split**: one thing became several.
- **optional**: kept, no longer universal.
- **retire**: gone, with the rule rehomed.

## Roles and work

| v1 | fate | v2 |
| --- | --- | --- |
| The three role charters PLAN, WORK, VERIFY | change | Situational charters EXECUTOR, ORACLE and REVIEWER in kernel/templates/org/roles/. A charter is adopted per task, never held for a session. |
| Universal separation of duties | retire | The router decides. R2 and above take an oracle authored before implementation and an independent review at acceptance; R0 and R1 self-merge, with R1 joining a sampled review pool. The one preserved separation is oracle authorship. |
| Work orders, per-file at L and queue rows at M | change | Task records under org/tasks/, one JSON file each per kernel/schemas/task-record.schema.json, written by the task command. |
| The eleven work types | optional | The intent line on the task record. Type no longer sets ceremony; the ruled tier does. Per-class testing expectations live in the delivery-testing pack. |
| The four intake doors | survive | Operator intent, cadence findings, verification failures and worker suggestions still open work. Suggestions land in docs/EOS_FEEDBACK.md at a venture and org/deviations.md here. |
| org/QUEUE.md at M and org/work/NEXT.md at L | retire | Task records, with org/TASKS.md as the derived view. The ordering that used to be the queue is the order of the open list. |
| docs/WORKLOG.md at S | retire | docs/TASKS.md, compiled from kernel/templates/TASKS.tpl.md: open items, questions for the operator, and one log line per finished Standard task. Express work lives in git history alone. |
| org/STATE.md as hand-written prose | change | A derived view regenerated by the integrator from the task records. Hand-editing it is a checker finding. |
| The Resume Packet at every close | optional | Seven keys inside the task record, written only when work is interrupted. A close that finished nothing to resume writes nothing. |
| Universal session logs | retire | Git is the log. The v1 logs S-0001 to S-0020 stay in org/logs/ untouched. High-assurance work keeps its record in the task file, oracle provenance included. |
| WIP limits, one at M and two at L | retire | Coordinator-assigned claims committed to the integration branch before dispatch, plus max_lanes in the policy. Unscheduled concurrent sessions are refused and quarantined. |
| The active_session claim line in STATE | retire | org/claims.json against kernel/schemas/claims.schema.json. Liveness comes from harness task state or a recorded PID; a timestamp alone never authorises taking a claim. |

## Risk and gates

| v1 | fate | v2 |
| --- | --- | --- |
| Risk tiers T1 to T3 at M, T1 to T4 at L | change | R0 to R3, ruled by the semantic router from declared facts unioned with derived signals, with machine-readable reasons. No rule maps a path alone to a tier. kernel/POLICY_SPEC.md is the law. |
| G1, automated gate | change | The mode's verification setting: targeted checks in Express, the affected set through the test map in Standard, full suites at integration and release. |
| G2, independent review | change | REVIEWER at R2 and above; a sampled pool at R1, default twenty per cent, tuned by measured escaped defects. |
| G3, human approval | split | The policy's approvals block for tier-level approval, and the action-time guard's require-approval and manual-only verdicts for individual actions. kernel/GUARD_SPEC.md holds the non-waivable floors. |
| G4, post-release verification | change | Release control and rollout practice in the devops-reliability pack. |
| G5, periodic audit | change | The monthly governance review sampling five items: live experiments, standing exceptions in org/decisions/ and contested rules. |
| Tier raised by VERIFY, never lowered | survive | Gate-time recomputation against the actual diff resolves upward only. The only way down is an audited exception: one-off by a REVIEWER on the record, or standing by an accepted ADR in org/decisions/ carrying an expiry date (ADR-0004). |
| Blanket test-first | retire | The adaptive testing law in the delivery-testing pack: timing by change class, with bug repros always first and invariants, money, security and public contracts taking acceptance before implementation. The timing ablation sets the profile defaults. |
| Three strikes | change | The circuit breaker: stop when three materially distinct hypotheses have each been tested and falsified and the latest attempt reduced no uncertainty. Retries count as one hypothesis. |
| Priorities P0 to P3 | optional | The order of the open list. Nothing in the kernel carries a separate priority scheme. |
| Definition of Done, universal baseline | change | Split across the mode's artefacts list in the policy and the acceptance criteria on the task, so a doc fix stops carrying a migration checklist. |

## Knowledge

| v1 | fate | v2 |
| --- | --- | --- |
| Doctrine modules | change | Packs under packs/, loaded in three levels: first paragraph always, PACK.md body on activation, organs on demand. |
| MODULE_SHAPE.md | change | packs/PACK_SHAPE.md. The pruning test, the line budgets and one-fork-per-guide survive intact; the definition of done is new and strict. It also left the protected set and now changes by ADR (ADR-0004). |
| The wargame corpus | survive | WG- ids are never renumbered or reused. Each v1 wargame lives under the pack that owns its decision, keeping its id, its argument and its worked rulings. |
| The wargame format | change | The guide format. New guides are `GD-<PACK>-NNN`, numbered per pack. Format left the protected set. |
| doctrine/WARGAME_INDEX.md | change | packs/GUIDE_INDEX.md, derived from guide front-matter. |
| The promotion arithmetic | survive | The ladder is still preference, advisory, default, binding. Two argued rulings from two ventures, or one plus a source with basis standard or evidence grade controlled, makes a binding candidate; binding needs an accepted ADR and Daniel. Inherited rulings still prove nothing. What is new is that a source can now carry the second half of the argument. |
| The ten-class type taxonomy | change | Eight orthogonal axes in kernel/METADATA_SPEC.md with minima that vary by kind. The v1 type field survives for EOS-internal files; the axes apply wherever a kind is declared. |
| registry/ | survive | Still the home of versioned fact. Canonical machine files now, registry/evidence.json and registry/coverage.json, with the Markdown views derived. |
| The voice law | split | Three scopes: binding for this repo's prose, default for venture documentation, preference for brand voice. |
| GUIDE.md, START.md, VISION.md | retire | GUIDE.md replaced by TOUR.md, which is rewritten by hand each release; START.md retired into the router and org/START.md; VISION.md merged into README.md. All three are preserved at the archive/v1-final tag. |

## Machinery

| v1 | fate | v2 |
| --- | --- | --- |
| kernel/SCALE_MATRIX.md, scales S, M and L | change | Scales S and ORG, M and L merged. The seed check reads the matrix at the seed's own pinned commit, so a v1-pinned seed is still judged by the v1 matrix and does not fail for being old. The v1 matrix is archived at archive/v1-final:kernel/SCALE_MATRIX.md. |
| kernel/SEED_RUBRIC.md | survive | Extended. The A-items keep their v1 check ids and gain D001 to D009, which cover compiled ancestry, the negative matrix, deferral follow-ups, guide resolution, the policy schema, the guard adapter and the seeded claims file. The five human items are unchanged. |
| Cadences in org/CADENCE.md | change | org/cadence.json, machine-readable, with a Markdown pointer beside it. Check S009 flags overdue rows. Cadences compile at ORG only; an S venture runs none. |
| Playbooks, org/playbooks/CATALOGUE.md at L | change | kernel/templates/org/PLAYBOOKS.tpl.md compiles at ORG. The EOS's own procedures are org/PLAYBOOKS.md, PB-E01 to PB-E10. |
| tools/eos_check.py | split | The tools/eos package, run as one command with five check series: E structural, S semantic, F freshness, B benchmark freeze, and D seed under --seed. tools/eos_check.py remains as a deprecation shim, and the v1 checker is kept at archive/v1-final:tools/eos_check.py because it was the parity anchor for the port. |
| The metadata-only checker | change | The semantic series checks operational truth: enum validity, supersession pairs, path and id resolution, derived drift, pack organs, machine facts against git reality, canonical-fact duplication, cadence overdue and cross-registry consistency. |

## What did not move

Front-matter on every file, derived indexes regenerated rather than
hand-written, append-only decisions, ventures pinning an EOS commit and
never auto-upgrading, and the rule that a red check is never weakened,
skipped or deleted. Those survived the audit because nothing in it
argued against them.
