# MIGRATION_MAP

What happened to every part of EOS v1 under ADR-0002, and where v2.1
moved a fate again. This is the reference the per-venture migration
playbook cites, and the answer to "where did that rule go" for anyone
who learned the system in July.

Five fates are used, and a retired concept always names where its
load-bearing rule now lives. One thing was dropped silently and the
row is below: v2 lost Genesis without recording it, which is how
ADR-0006 came to restore it.

- **survive**: the same thing, still binding.
- **change**: the same job, a new mechanism.
- **split**: one thing became several.
- **optional**: kept, no longer universal.
- **retire**: gone, with the rule rehomed.

## Roles and work

| v1 | fate | v2 |
| --- | --- | --- |
| The three role charters PLAN, WORK, VERIFY | change | Situational charters EXECUTOR, ORACLE and REVIEWER in kernel/templates/org/roles/. A charter is adopted per task, never held for a session. |
| Universal separation of duties | retire | The router decides. R2 and above take an oracle authored before implementation and an independent review at acceptance; R0 and R1 self-merge, with R1 joining a sampled review pool. The one preserved separation is oracle authorship. |
| Work orders, per-file at L and queue rows at M | change | Task records under org/tasks/, one JSON file each per kernel/schemas/task-record.schema.json, written by the task command. |
| The eleven work types | optional | The intent line on the task record. Type no longer sets ceremony; the ruled tier does. Per-class testing expectations live in the delivery-testing pack. |
| The four intake doors | survive | Operator intent, findings from the monthly pass, verification failures and worker suggestions still open work. A venture's suggestions land in its docs/EOS_FEEDBACK.md and reach the EOS through the harvest. Here a suggestion opens a task record or, for ordinary work, is the commit message (ADR-0008). |
| org/QUEUE.md at M and org/work/NEXT.md at L | retire | Task records, with org/TASKS.md as the derived view. The ordering that used to be the queue is the order of the open list. This repository kept an org/QUEUE.md pointer file through v2 saying the queue had moved; it was cut at release, because by then it pointed at a directory the router and the task command already name. |
| docs/WORKLOG.md at S | retire | docs/TASKS.md, compiled from kernel/templates/TASKS.tpl.md: open items, questions for the operator, and one log line per finished Standard task. Express work lives in git history alone. |
| org/STATE.md as hand-written prose | change | A derived view regenerated by the integrator from the task records. Hand-editing it is a checker finding. |
| The Resume Packet at every close | optional | Seven keys inside the task record, written only when work is interrupted. A close that finished nothing to resume writes nothing. |
| Universal session logs | retire | Git is the log. The v1 logs S-0001 to S-0020 stay in org/logs/ untouched. High-assurance work keeps its record in the task file, oracle provenance included. |
| WIP limits, one at M and two at L | retire | Coordinator-assigned claims committed to the integration branch before dispatch. Unscheduled concurrent sessions are refused and quarantined. `parallelism.max_lanes` in org/policy.json is a declared ceiling that nothing reads: the v2.1 build ran twelve lanes and an integrator against a value of four and no check noticed. |
| The active_session claim line in STATE | retire | org/claims.json against kernel/schemas/claims.schema.json. Liveness comes from harness task state or a recorded PID; a timestamp alone never authorises taking a claim. |

## Risk and gates

| v1 | fate | v2 |
| --- | --- | --- |
| Risk tiers T1 to T3 at M, T1 to T4 at L | change | R0 to R3, ruled by the semantic router from declared facts unioned with derived signals, with machine-readable reasons. No rule maps a path alone to a tier. kernel/POLICY_SPEC.md is the law. |
| G1, automated gate | change | The mode's verification setting: targeted checks in Express, the affected set through the test map in Standard, full suites at integration and release. |
| G2, independent review | change | REVIEWER at R2 and above; a sampled pool at R1, default twenty per cent, tuned by measured escaped defects. |
| G3, human approval | split | The policy's approvals block for tier-level approval, and the action-time guard's require-approval and manual-only verdicts for individual actions. kernel/GUARD_SPEC.md holds the non-waivable floors. |
| G4, post-release verification | change | Release control and rollout practice in the devops-reliability pack. |
| G5, periodic audit | change | The monthly governance review sampling five items: live experiments, standing exceptions in org/decisions/ and contested rules. |
| Tier raised by VERIFY, never lowered | survive | Gate-time recomputation against the actual diff resolves upward only. The only way down is an audited exception: one-off by a REVIEWER on the record, or standing by an accepted ADR in org/decisions/ carrying an expiry date (ADR-0004). |
| Blanket test-first | retire | Verification stages on risk and on measured stability signals, never on a completeness percentage (ADR-0006). The delivery-testing pack holds the staging and the timing defaults the ablation set. What binds is not ordering but independence: the artefact that decides whether a change is correct is not authored by the agent holding that implementation in context. No rule requires tests first any more: the test-first half of packs/coding B1 dropped to a default, and what B1 binds now is independence plus the oracle having been seen to fail. |
| Three strikes | change | The circuit breaker: stop when three materially distinct hypotheses have each been tested and falsified and the latest attempt reduced no uncertainty. Retries count as one hypothesis. |
| Priorities P0 to P3 | optional | The order of the open list. Nothing in the kernel carries a separate priority scheme. |
| Definition of Done, universal baseline | change | Split across the mode's artefacts list in the policy and the acceptance criteria on the task, so a doc fix stops carrying a migration checklist. |

## Knowledge

| v1 | fate | v2 |
| --- | --- | --- |
| Doctrine modules | change | Packs under packs/, loaded in three levels: first paragraph always, PACK.md body on activation, organs on demand. |
| MODULE_SHAPE.md | change | packs/PACK_SHAPE.md. The pruning test and one-fork-per-guide survive intact and the definition of done is new and strict, but the line budgets warn rather than fail from ADR-0008 on, with the pruning test and the review passes catching the bloat instead. It left the protected set and now changes by ADR (ADR-0004). |
| The wargame corpus | survive | WG- ids are never renumbered or reused. Each v1 wargame lives under the pack that owns its decision, keeping its id, its argument and its worked rulings. |
| The wargame format | change | The guide format. New guides are `GD-<PACK>-NNN`, numbered per pack. Format left the protected set. |
| doctrine/WARGAME_INDEX.md | change | packs/GUIDE_INDEX.md, derived from guide front-matter. |
| The promotion arithmetic | survive | The ladder is still preference, advisory, default, binding. Two argued rulings from two ventures, or one plus a source with basis standard or evidence grade controlled, makes a binding candidate; binding needs an accepted ADR and the operator. Inherited rulings still prove nothing. What is new is that a source can now carry the second half of the argument. |
| The ten-class type taxonomy | change | Nine orthogonal axes in kernel/METADATA_SPEC.md, the ninth being conflicts_with, added by ADR-0006 so a rule or a lesson can name what it contradicts. ADR-0008 cut the minima to what changes behaviour: summary, type and tags everywhere, then authority, applies_when, sources and review where they do. The v1 type field survives for EOS-internal files; the axes apply wherever a kind is declared. |
| registry/ | survive | Still the home of versioned fact. Canonical machine files now, registry/evidence.json, registry/coverage.json and, from ADR-0006, registry/lessons.json, with the Markdown views derived. |
| The voice law | split | Three scopes in packs/writing-content: eos-internal for this repository's prose, venture for a venture's documentation, and brand for how a venture sounds to its market. All three are defaults or preferences after the ADR-0008 audit, and nothing changed in practice: check E004 still fails the build on an em-dash and AGENTS.md still carries the rule. |
| GUIDE.md, START.md, VISION.md | retire | GUIDE.md replaced by TOUR.md, which is rewritten by hand each release; START.md retired into the router and org/START.md; VISION.md merged into README.md. All three are preserved at the archive/v1-final tag. |

## Machinery

| v1 | fate | v2 |
| --- | --- | --- |
| kernel/SCALE_MATRIX.md, scales S, M and L | change | Scales S and ORG, M and L merged. The seed check reads the matrix at the seed's own pinned commit, so a v1-pinned seed is still judged by the v1 matrix and does not fail for being old. The v1 matrix is archived at archive/v1-final:kernel/SCALE_MATRIX.md. |
| kernel/SEED_RUBRIC.md | survive | Extended. The A-items keep their v1 check ids and gain the D-series, which covers compiled ancestry, the negative matrix, deferral follow-ups, guide resolution, the policy schema, the guard adapter, the seeded claims file and, from v2.1, the compiled Genesis templates and the acceptance spine. D005 carries no A-item row because only a v1-pinned seed can fail it: v2 ships nothing empty. The five human items are unchanged. |
| Cadences in org/CADENCE.md | change | org/cadence.json, machine-readable, and nothing beside it: the Markdown pointer file was cut at release because it only said the JSON was next door. Check S009 flags overdue rows. In this repository one row survives, the monthly pass, because ADR-0008 folded four cadences into it and made the rest event-triggered. The inception-drill, projects-review and benchmark-freshness rows were deleted at release rather than left carrying no date, each of them on-demand with nothing that could ever make it due. Cadences compile at ORG only; an S venture runs none. |
| Playbooks, org/playbooks/CATALOGUE.md at L | change | kernel/templates/org/PLAYBOOKS.tpl.md compiles at ORG. The EOS's own procedures are org/PLAYBOOKS.md, PB-E01 to PB-E12. |
| PB-001, Genesis, the venture playbook that turned a signed seed into a design set | change | **v2 dropped this with no row, and v2.1 restored it as something narrower** (ADR-0006). Genesis is now one compiled phase, inception/GENESIS.md, run once in the venture's own repo after the seed gate, producing research packets, a product map, work packages and an acceptance spine that starts red. It is a launch decision the operator takes, not a standing playbook, and the EOS never runs it. Two things came forward from PB-001 because they earned it: the scale grading, and the acceptance walk-through written as a failing suite that goes green journey by journey. Everywhere else in this repository, Genesis meaning the v1 playbook is glossed as history. |
| tools/eos_check.py | split | The tools/eos package, run as one command with five check series: E structural, S semantic, F freshness, B benchmark freeze, and D seed under --seed. The v1 checker is kept at archive/v1-final:tools/eos_check.py because it was the parity anchor for the port. The old path still resolves in the tree: ADR-0001 names it and is append-only, so a deprecation shim sits there and forwards to the package. |
| The metadata-only checker | change | The semantic series checks operational truth: enum validity, supersession pairs, path and id resolution, derived drift, pack organs, machine facts against git reality, cadence overdue, cross-registry consistency, and from v2.1 the evidence and lesson ledgers against their schemas plus the conflicts a lesson declares. |

## What did not move

Front-matter on every file, derived indexes regenerated rather than
hand-written, append-only decisions, ventures pinning an EOS commit and
never auto-upgrading, and the rule that a red check is never weakened,
skipped or deleted. Those survived the audit because nothing in it
argued against them.
