# Baseline, 2026-08-15

Captured on branch `eos/audit-research-expansion` at commit
`a2e70c51a8a79672b2e395bc1db3084a6e862a5b`, before any change. Every figure
here was produced by reading the tree, not by reading the prose about it. The
numbers exist so that later claims about growth, proportionality and repair
have something to be measured against.

and 3.14, so cross-platform behaviour is held by the matrix rather than by an

library is linear in that figure and tolerable, so the proportionality risk
sits in what a seed carries, not in the size of the index that lists the
library.

## The routing observation

Reading the 25 task records directly:

| Measure | Value |
| --- | --- |
| Records ruled R0 | 21 |
| Records with an empty reasons list | 21 |
| Records where the ruled tier came out below the proposed tier | 22 |
| Records declaring any side effect | 2 |

`tools/eos/taskops.py:157` passes an empty dict as the derived-signals slot, so
routing at record creation reads declarations only and no diff. The code says
so and `kernel/POLICY_SPEC.md` says so. What no file says is the consequence:
across the whole v2.1 build the thirteen factors never fired, and T-0013
proposed R3 and was ruled R0.

The recomputation that would catch this is `python -m tools.eos route --diff`,
run by a person at the merge. Nothing in the tree records it having been run.

## What this baseline is for

Later work packages must show, against these figures, that repairs landed, that
the library grew, and that compiled seeds did not grow with it.
