# SCALE_MATRIX

The live law of what a compiled seed contains. The v2 scales are S and
ORG; v1's M and L merge into ORG. This file is where the seed check
parses the matrix. The v1 matrix it replaced, with its S, M and L
columns, is at archive/v1-final:kernel/SCALE_MATRIX.md, and a seed
resolves whichever matrix its pinned commit carries.

Reading the numbers honestly: S is fourteen files, of which CLAUDE.md
is a byte copy, the compile report is meta and five are blank Genesis
forms, so the operating surface is seven. A blank form is not operating
surface: nobody reads it until the venture decides to run Genesis. ORG
is twenty-five files on the same accounting, an operating surface of
eighteen.

The scale is ruled at Session 0 by WG-EOS-001 and recorded in the
lock-book header. A rescale from S to ORG recompiles the delta
between the columns and migrates the open items of docs/TASKS.md
into task records.

Two rulings the table carries without arguing them. The five Genesis
forms ship at both scales: a blank form costs nothing, and a venture
rescaling from S to ORG should not discover it never had a work package
form. Running the phase stays the operator's launch decision.
org/GRAPH_BUILD.md is ORG only, because it names org/claims.json as its
mutex and S has no claims file; a compiled copy at S would point at a
file that is not there. Its template carries no scale fences for that
reason: nothing compiles it at S, so an S form would be a block no
compiler could ever reach. An S venture that needs a second writer
reads packs/agentic-swarm and rescales.

## Directories and derived views

Nothing ships empty. Directories appear with their first content and
never at compile: org/tasks/ with the first task record,
org/decisions/ with the first ADR, and org/incidents/ with the first
incident. docs/packages/, docs/research/ and docs/lenses/ arrive the
same way, when the venture copies its first work package, research
packet or lens contract out of the forms in docs/genesis/. Seeded empty
for the claims file means the schema's minimum: the version, the
assigned date and an empty lanes list. The derived views org/TASKS.md
and org/STATE.md are regenerated by the tooling once records exist; they
are never seed files and never hand-edited. At S, docs/TASKS.md is a
seed file because S runs without the integrator tooling.

## Trigger add-ons

Attached by trigger regardless of scale, named in the lock-book
header addons: list; the seed check enforces the files of every
named add-on. An add-on without a kernel source is authored at
Session 0 from the doctrine the trigger names and recorded in the
compile report as authored.

| addon | file | source | trigger |
| --- | --- | --- | --- |
| compliance | org/COMPLIANCE.md | authored per packs/legal-licensing, which routes regulatory duties to data | personal or regulated data present; at S, rescale to ORG first |
| ops-runbook | ops/runbooks/deploy.md | authored per the stack profile | anything deployed with server state |
| restore-test | org/cadence.json gains the restore-test row | authored per the restore-proof rules in packs/devops-reliability | production data exists |
